# Context codebook v03

Changed from v02: `template` Include and `personal-config` Exclude send a repository whose README says it may serve as a starting point to `template`, even if it is one person's own setup; `unclear` Include adds repositories no longer on GitHub with no dataset description (researchers' v03 decisions, `docs/context-brief.md`).

First context codebook, written from the researchers' brief (`docs/context-brief.md`, #41). Each label classifies the repository a skill lives in (the repo of the skill's representative copy), not the skill: what the repository is for, and what role its SKILL.md files play there. One main kind per repository; a second only when the repository clearly serves two purposes.

## operational-project: Operational project

### Definition
The repository exists to build or run something else (an application, library, service, tool or research code), and its skills support work on that project.

### Include
- Source code dominates; a few skills tied to the project's own stack or conventions.

### Exclude
- Repositories meant to be copied as a starting point: goes to `template`.
- Repositories whose product is the skills themselves: goes to `skill-catalog`.

### Examples
- n8n-io/n8n: "Fair-code workflow automation platform with native AI capabilities."
- mem0ai/mem0: "Universal memory layer for AI Agents"

## skill-catalog: Catalog or collection of skills

### Definition
The skills themselves are the product: the repository collects, curates, lists or distributes skills for others to install or copy.

### Include
- Curated or "awesome" lists, registries, marketplaces, official skill collections.
- One person's own collection of skills published for others to install, whether the skills were collected from others or written by the owner: the test is what the repository offers.

### Exclude
- One or a few skills used for the repository's own work: goes to `operational-project`.
- A handful of skills written to teach how skills work: goes to `demonstration`.

### Examples
- ComposioHQ/awesome-claude-skills: "A curated list of awesome Claude Skills, resources, and tools for customizing Claude AI workflows"
- laravel/agent-skills: "Laravel official collection of agent skills"

## template: Template or starter

### Definition
The repository is meant to be copied as the start of a new project.

### Include
- Repositories marked as GitHub templates; starters, boilerplates, scaffolds, starter kits.
- Repositories whose README says they may serve as a starting point for others, even if they are one person's own setup.

### Exclude
- Guides that only contain copy-paste snippets: goes to `demonstration`.

### Examples
- epicweb-dev/epic-stack: "This is a Full Stack app starter with the foundational things setup and configured for you to hit the ground running on your next EPIC idea."
- fullstackhero/dotnet-starter-kit: "Production Grade Cloud-Ready .NET 10 Starter Kit"

## demonstration: Demonstration, example or tutorial

### Definition
The repository shows how something works or teaches it, and is not meant for real use as is.

### Include
- Examples, demos, tutorials, guides, courses, workshop or talk material.

### Exclude
- Starters meant to be copied and filled in: goes to `template`.

### Examples
- luongnv89/claude-howto: "A visual, example-driven guide to Claude Code"
- Unity-Technologies/PhysicsExamples2D: "Examples of various Unity 2D Physics components and features."

## personal-config: Personal configuration

### Definition
A person's own environment setup (dotfiles, editor and shell configuration, personal agent setup), with skills as part of that configuration.

### Include
- Dotfiles repositories; personal Claude Code or agent configuration.

### Exclude
- Configuration whose README says it may serve as a starting point for others, even if it is one person's own setup: goes to `template`.
- A person's own collection of skills offered for others to install, even if the owner wrote them: goes to `skill-catalog`.

### Examples
- freekmurze/dotfiles: "My personal dotfiles"
- jackfranklin/dotfiles: "My dotfiles for my dev environment, compromising of tmux, vim, zsh and git."

## unclear: Unclear or other

### Definition
The kind cannot be told from the repository (empty or missing README, deleted repository with little metadata), or it fits none of the kinds above. Use sparingly: a repository that fits a kind imperfectly gets that kind; repeated "other" cases with something in common become a PROPOSED_NEW for the researchers.

### Include
- Repositories with an empty or missing README, or a deleted repository with little metadata, where nothing says what the repository is for.
- Repositories no longer on GitHub (no README, files or history to classify from) with no description in the dataset, whatever their name, language or skill paths suggest. If the dataset description states what the repository is, use that kind instead.

### Exclude
- Repositories that fit one of the kinds above, even imperfectly: goes to that kind.

### Examples
- zhu637882-stack/jiaoyi: "test"
