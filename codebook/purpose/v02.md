# Purpose codebook v02

v01 is built bottom-up from the Round 0 open codes: run 4 (open-coder agent, 46 codes) and run 5 (brendan, 12 codes). Run 6 is not used (see `docs/purpose-brief.md`). Each category is one kind of work a skill codifies; subject areas are not categories. Codes that could not be placed are listed in the comment at the end.

## write-tests: Write and guide tests

<!-- sources: open-coder: write test cases, write python test fixtures, guide test-driven implementation, select testing frameworks; brendan: Testing -->

### Definition
Writes, plans or guides automated tests: test cases, fixtures, mocks, test-driven workflows, and the choice of test frameworks.

### Include
- Writing test cases or acceptance criteria, including before implementation.
- Test fixtures, mock patterns and testing conventions for a given stack.
- Choosing a testing framework or test type (unit, integration, API).

### Exclude
- Reviewing existing code or changes for bugs and quality: goes to `review-validate`.
- Implementing the feature that the tests cover: goes to `write-code`.

### Examples
- 00181699d0e3b40ea90dbbd48e7757c84f51783f: "Define test cases BEFORE implementation, ensuring every API, business rule, and user journey has verifiable acceptance criteria"
- 00562419b4b03388123490d294289ef0d96a957c: "Pytest fixture strategies, mock patterns, and service-specific testing quirks for aithena Python services"

## review-validate: Review, audit and validate

<!-- sources: open-coder: review code changes, review ui accessibility, audit architecture alignment, critically review artifacts, verify compliance controls, triage github inbox, validate automation job templates, validate network topology, validate physics model code; brendan: Validation -->

### Definition
Checks existing code, designs, documents, interfaces or configurations against a standard, requirement or checklist, and reports findings or a pass/fail verdict.

### Include
- Code review of changes for bugs, security and code quality.
- Audits of an implementation or document against approved architecture or compliance controls.
- Accessibility and contrast checks against WCAG.
- Triage of issues and pull requests against templates and contribution rules.

### Exclude
- Writing new tests or test cases: goes to `write-tests`.
- Giving general expert guidance without checking a specific artifact: goes to `advise-expert`.
- Changing the artifact itself: goes to `write-code` or `configure-operate`.

### Examples
- 00fa616f2fc02bcead4010afb32e1ffcf619cfc4: "Review source files changed during a phase for bugs, security issues, and code quality problems"
- 00366eef12736b1e0b1f2a3fe0ef7e796be5e48d: "Verify text and non-text contrast against WCAG 2.2 (1.4.3, 1.4.6, 1.4.11) and APCA."
- 00aa3df86cbfbc66b433f1f5633f3ea37481df3b: "Audit implementation shape against approved architecture and design artifacts for governance parity."

## write-code: Write and integrate code

<!-- sources: open-coder: build mcp servers, configure api gateway, implement cloud file storage, implement redis caching, implement regime-switching models; brendan: Code creation -->

### Definition
Writes application, server, component or algorithm code, or integrates a library or service into a codebase.

### Include
- Building a server, component or API that other tools or clients call.
- Implementing a specific algorithm or feature in code.
- Adding a service integration (storage, caching) into an application's code.
- Library and API usage guides for writing code against them.

### Exclude
- Designing the architecture or data model before coding: goes to `design-plan`.
- Setting up build, deployment or network infrastructure: goes to `configure-operate`.
- Writing tests for the code: goes to `write-tests`.

### Examples
- 0067f5d456dc4b20c89b831e44f6cea72eeb2dd4: "Build production-quality MCP (Model Context Protocol) servers that expose tools, resources, and prompts"
- 00fbe1da5f7c75ae27deb720339ca04c73b69b8f: "Implement Redis as a production support layer, not as a second database."

## version-control: Version control and code hosting

<!-- added in v02 from the 2026-11-25 researcher decision (brief: docs/purpose-brief.md); no Round 0 sources -->

### Definition
Runs or sets rules for source-control work: staging and committing, commit messages, branching, pull requests, merging, rebasing, pushing, and changelog or release steps.

### Include
- Commit-and-push helpers.
- PR size, branch-protection and merge rules.
- Preparing and submitting a pull request.
- Merging feature or stacked branches.

### Exclude
- Reviewing the code in a pull request: goes to `review-validate`.
- Operating a hosted service's issues, inbox or settings through its API: goes to `integrate-external`.
- CI/CD pipelines and build tooling: goes to `configure-operate`.

### Examples
- 00cd790c1e4e9914e7e8d56fcc1c50ee07ce78ca: "Analyze all uncommitted changes, generate a comprehensive yet succinct commit message, stage, commit, and push in one step."
- 006bc2290cedf0d7d5743fbb65d00b3e16d1cbc9: "Prepares and submits a pull request for feature or bugfix work."
- 005dc0cb2c08aa3dc10144ee2e291a332219c543: "Safely merge feature branches, bookmarks, and stacked changes into main."

## design-plan: Design and plan

<!-- sources: open-coder: add ux delight, design data models, design kubernetes infrastructure, write design documents -->

### Definition
Produces designs, architecture, data models, specifications, UX concepts or plans that are written down before, or instead of, implementation.

### Include
- Technical design documents, RFCs and tech specs.
- Architecture and infrastructure design, such as platform or multi-cluster design.
- Data model design guidelines.
- UX concept work: finding places to add delight or personality to a product interface.
- UI and visual design rules, such as colour and UI states.

### Exclude
- Checking a finished design against standards: goes to `review-validate`.
- Maintaining a cumulative system specification as a record: goes to `agent-knowledge`.
- Carrying out a written plan: goes to `orchestrate-workflows`.

### Examples
- 003eeeff35a3fb3ffc4aaaa0f599123a5058d9c8: "Write a technical design document (RFC, tech spec, design doc, or plan) before implementing a feature"
- 00b73439353d835887e8f6af756b30fa3d297a63: "Designing Kubernetes platform architecture or multi-cluster strategy"

## configure-operate: Configure and operate systems

<!-- sources: open-coder: capture network traffic, configure build tooling, replay pipeline runs -->

### Definition
Sets up, configures, runs or inspects build tooling, network links and pipeline runs.

### Include
- Configuring builds, dependencies and artifact generation.
- Capturing or inspecting network traffic on lab or network links.
- Re-running or debugging a stored pipeline run.
- Running local tools and automating the operating system, such as a local CLI or window control.

### Exclude
- Designing the architecture of infrastructure: goes to `design-plan`.
- Writing application code that uses a service: goes to `write-code`.
- Calling a hosted service's API (for example GitHub or Confluence): goes to `integrate-external`.
- Source-control work such as commits, branches and pull requests: goes to `version-control`.

### Examples
- 00c38e92580c2bc2e0908b2c85eed0af2f6bb5e2: "Use this skill when configuring builds, dependencies, testing, or artifact generation using Gradle."
- 00e56bc7f964fa0e3b38466fd0a25b6041c3159e: "Start and stop packet captures on links in GNS3 projects."

## orchestrate-workflows: Orchestrate agent work

<!-- sources: open-coder: execute written plans, plan multi-agent project, process queued agent tasks -->

### Definition
Directs how agents carry out multi-step work: executing a written plan, coordinating several agents, or processing queued instructions.

### Include
- Executing a written implementation plan with review checkpoints.
- Starting a project in which several agents collaborate.
- Picking up queued instructions and reporting back.

### Exclude
- Writing the plan or design document itself: goes to `design-plan`.
- Keeping session context or memory between runs: goes to `agent-knowledge`.

### Examples
- 0033699eb5500379694d489a4183436e9be98e41: "Use when you have a written implementation plan to execute in a separate session with review checkpoints"
- 01695901e62b50f80863a70170f2f4e621308d0b: "Pick up one queued instruction, execute it, then publish a structured report."

## agent-knowledge: Maintain agent and project knowledge

<!-- sources: open-coder: maintain agent memory notes, maintain system specification, manage org notes, map codebase modules, restore session context; brendan: Project knowledge -->

### Definition
Keeps knowledge that agents or people reuse across sessions: memory files, session context, specifications, notes, and maps of a codebase.

### Include
- Agent memory or learnings files that persist between runs.
- Restoring session or project context before work starts.
- Maintaining a cumulative system specification.
- Mapping a codebase's modules and symbols for later reference.
- Personal or organisation note systems.

### Exclude
- Designing a new system or data model: goes to `design-plan`.
- Mapping knowledge gaps for a topic or market research: goes to `analyze-research`.

### Examples
- 009f6859aecb945a798af8ce89b38a1675290746: "Read + write the per-pair learnings.md file so the running agent builds up institutional knowledge over time"
- 00e9d1dc478bca25eeb3565c42a781b2e69aa658: "context recovery + governance before any work."

## analyze-research: Research, analyze and summarize

<!-- sources: open-coder: build financial market dashboards, conduct market research, map knowledge gaps, summarize external content; brendan: Data analysis -->

### Definition
Researches a topic, analyzes data, or condenses content into a report, dashboard, summary or knowledge map.

### Include
- Market or competitor research producing a cited report.
- Dashboards that combine data from several sources.
- Summaries of videos, articles, tickets or repositories.
- Knowledge maps that structure what is known about a topic.

### Exclude
- Checking an artifact against a standard, or triaging issues: goes to `review-validate`.
- Downloading media: goes to `produce-media`.
- Writing text for an audience, such as copy or postmortems: goes to `write-content`.

### Examples
- 00fdf30b13f5605d2c122250ccfb016f043a1390: "produces one consolidated, cited market+competitor report"
- 00134ec76942976714a6ed9533e6b9536ab8b020: "Build macroeconomic and rates dashboards combining macro indicators, yield curves, inflation breakevens, and swap rates."
- 00a15635eb311dd05052cb594d719783dd731081: "Summarize any content — YouTube video, Medium article, Jira issue, GitHub repo, AWS/Amazon blog, or Slack thread."

## write-content: Write prose and reports

<!-- sources: open-coder: write editorial copy, generate incident postmortem; brendan: Non-code content -->

### Definition
Writes text that people read: editorial and site copy, articles, and structured reports such as postmortems.

### Include
- Writing or editing articles, headlines and site copy.
- Generating a structured postmortem from a campaign's artifacts.
- Generating or formatting documentation, such as API reference documents and documentation formats, even when a build step produces it.

### Exclude
- Technical design documents and specifications: goes to `design-plan`.
- Summaries of external content: goes to `analyze-research`.

### Examples
- 008ee81c318e9b83f0e14fa9d49e65fb28eb59f9: "Use when writing, editing, or evaluating SwissCapital.news copy, articles, headlines, decks, homepage copy"
- 00b56fd8884f2d6cd0067ebe232bff2439eb99b1: "Auto-generates a structured postmortem from a completed campaign."

## produce-media: Produce and retrieve media

<!-- sources: open-coder: produce video visuals, download online media -->

### Definition
Creates visual or audio media from source material, or downloads video, audio and subtitles.

### Include
- Turning a transcript line into a visual or video beat.

### Exclude

## integrate-external: Operate external services and tools

<!-- sources: open-coder: automate email tasks, find and install api skills, manage confluence documentation, manage github repositories; brendan: API usage -->

### Definition
Uses an external service or tool through its API, CLI or connector to read, change or manage what it holds.

### Include
- Email, documentation or code-hosting actions through a connector or CLI.
- Finding and installing skills or APIs from a catalog.
- Routine use of a hosted service's API.

### Exclude
- Writing application code that uses a service: goes to `write-code`.
- Setting up a local build, network or pipeline tool: goes to `configure-operate`.
- Running a local tool or automating the operating system, such as a local CLI or window control: goes to `configure-operate`.
- Source-control work such as commits, branches and pull requests: goes to `version-control`.

### Examples
- 006b86d5adb18c3aa56723bd9e505a6cce4e3d4a: "Automate Gmail tasks via Rube MCP (Composio): send/reply, search, labels, drafts, attachments."
- 00e785a3197b960d10e0f366f0eabf1fce7af552: "This skill helps manage GitHub repositories using GitHub CLI (gh)."

## advise-expert: Advise as a domain expert

<!-- sources: open-coder: advise database administration -->

### Definition
Gives expert guidance on one technology or domain, answering questions and recommending practices, without auditing a specific artifact or doing the work itself.

### Include
- Expert-persona skills that advise on a single technology.
- Fact-checked, version-aware guidance on administering a system.

### Exclude
- Checking a named artifact against a standard: goes to `review-validate`.
- Carrying out the administration: goes to `configure-operate`.

### Examples
- 0005bfdfffae9c0aa20b16c806c33b47bb41cc1c: "MongoDB expert advisor with fact-checked, version-aware guidance."
